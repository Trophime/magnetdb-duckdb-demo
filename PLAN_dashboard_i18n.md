**Note on Babel/gettext vs. a plain dict.** A hand-rolled Python dict is quicker to bolt on for 2 languages but has no automated string extraction and does nothing for locale-aware number/date formatting. Babel/gettext costs more up front — a new dependency, an extract/compile step (`pybabel extract → init/update → compile`), `.po`/`.mo` catalogs to maintain, and care needed where translation is called outside an active Flask request context (handled here by not depending on request context at all — locale is a persisted preference, resolved once and reloaded on change, same model as `style.json`). It's adopted here specifically because locale-correct number/date formatting in figures and tables was an explicit requirement, which a plain dict cannot provide.

**Figures vs. tables — two different mechanisms.** Figure axis ticks and hover text are rendered client-side by Plotly.js using d3-format, so their locale correctness comes from a vendored Plotly.js locale bundle + `config={"locale": lang}` on each `dcc.Graph` — Babel has no visibility into that layer. `dash_table.DataTable` columns are rendered from Python-supplied values, so that's where `babel.numbers`/`babel.dates` formatting actually applies.
